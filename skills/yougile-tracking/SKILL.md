# YouGile

Клиент YouGile REST API v2. Один файл на Python, только стандартная библиотека,
нужен Python 3.10 или новее.

## Подключение

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/skills/yougile-tracking/scripts/yg.py" setup
python3 "${CLAUDE_PLUGIN_ROOT}/skills/yougile-tracking/scripts/yg.py" --selfcheck
```

`CLAUDE_PLUGIN_ROOT` подставляется, когда скилл установлен плагином. Если он
просто скопирован в `~/.claude/skills/yougile-tracking`, путь к скрипту -
`~/.claude/skills/yougile-tracking/scripts/yg.py`.

`setup` требует настоящего терминала: пароль читается скрытым вводом. Готовый
ключ можно положить в переменную `YOUGILE_API_KEY`, на Windows это
единственный способ.

## Быстрые команды

```bash
YG="python3 ${CLAUDE_PLUGIN_ROOT}/skills/yougile-tracking/scripts/yg.py"

$YG users_me '{}'                              # свой id, нужен для "assigned"
$YG projects_list '{}'
$YG boards_list '{"projectId":"<id-проекта>"}'
$YG columns_list '{"boardId":"<id-доски>"}'
$YG tasks_list '{"columnId":"<id-колонки>","all":true}'
$YG tasks_create '{"title":"Починить форму входа","columnId":"<id-колонки>"}'
$YG tasks_update '{"id":"<id-задачи>","completed":true}'
$YG --list                                     # имена всех 70 инструментов
```

Аргументы это один объект JSON, `-` читает их из stdin. Полный справочник с
инструментами, полями и цветами: `references/api.md`.

## Как создать задачу

Идентификаторы связаны цепочкой, и колонку нельзя узнать, не пройдя её сверху
вниз. Порядок такой:

1. `projects_list '{}'` - найти проект по названию, взять его `id`.
2. `boards_list '{"projectId":"..."}'` - найти доску внутри проекта.
3. `columns_list '{"boardId":"..."}'` - найти колонку, обычно нужна первая по
   порядку, если пользователь не назвал другую.
4. `users_me '{}'` или `users_list '{}'` - взять id исполнителя, если задачу
   нужно на кого-то назначить.
5. `tasks_create '{"title":"...","columnId":"...","assigned":["..."]}'` -
   создать карточку.

Если на любом шаге совпадений несколько, спросите, какой из них нужен, вместо
того чтобы брать первый попавшийся: проекты и доски часто называются похоже.

## Подводные камни

- **Пагинация.** Списки отдают 50 строк по умолчанию и 1000 максимум. Передайте
  `"all": true`, и клиент сам запросит страницы по 1000 строк, пока `paging.next`
  не станет `false`, и вернёт всё одним массивом. Без этого флага смотрите
  `paging.next` и листайте через `offset`, иначе незаметно работаете с куском
  данных: `paging.count` это размер полученной страницы, а не общее число.
- **Считать задачи лучше без фильтров.** `tasks_list '{"all":true}'` без `columnId`
  отдаёт все задачи, видимые ключу, сразу по всем проектам и доскам. Обход
  доска-колонка-задачи для подсчёта не годится: карточки, вынутые из колонки
  (`columnId: "-"`), в него не попадут и счёт молча занизится.
- **Видно только то, что доступно аккаунту.** Списки ограничены правами ключа, а
  не всей компанией: в компании задач может быть кратно больше, чем вернёт API.
  Отвечая на вопрос «сколько всего», это стоит оговаривать.
- **Удаление.** DELETE для задач, досок, проектов и колонок не существует.
  Удаляют через `*_update` с `{"deleted": true}`, а чтобы увидеть удалённое,
  передают `includeDeleted: true`. `columnId: "-"` вынимает задачу из колонки.
- **Цвета разного типа.** У колонки цвет это число от 1 до 16, у задачи строка
  вида `task-red`.
- **Чеклисты перезаписываются целиком.** Прочитать задачу, поправить массив,
  записать его обратно полностью.
- **Повторы запросов.** Клиент сам повторяет запрос при 429 и пятисотых, но
  `POST` повторяет только с `idempotencyKey` в теле, иначе оборвавшееся
  создание завело бы дубль.
- **Ограничение частоты:** 50 запросов в минуту на компанию.

## Ссылки на задачи

`tasks_get` возвращает `idTaskProject` - короткий код задачи внутри проекта,
например `TASK-42`. Задача открывается на весь экран по адресу
`https://ru.yougile.com/team/messenger#TASK-42`.

## Разметка описаний

Поле `description` это HTML. Markdown не разбирается вообще: `## Заголовок`,
`**жирный**` и `- пункт` приходят как обычные символы, а одиночный перевод
строки схлопывается.

Что работает:

- Текст: `<p>`, `<br>`, `<strong>`, `<i>`.
- Заголовки: только `<h4>`. Уровни крупнее вырезаются, поэтому многоуровневую
  структуру приходится держать на жирном тексте внутри `<h4>`.
- Списки: `<ul><li>`, вложенность через ещё один `<ul>` внутри `<li>`.
- Ссылки: `<a href="URL" target="_blank" rel="noopener noreferrer">текст</a>`.
- Выделение: `<span style="background-color:#B2D995">текст</span>`.
- Отступ между блоками: абзац с неразрывным пробелом внутри.
- Чекбоксы: собственная структура редактора, `<input type="checkbox">` внутри
  `<label class="todo-list__label">` внутри `<ul class="todo-list">`, текст в
  `<span class="todo-list__label__description">`. Для отмеченного добавляется
  `checked="checked"`. Символ `☐` останется символом, а `- [ ]` останется
  текстом.

Для списка дел внутри карточки лучше поле `checklists`, а не разметка с
чекбоксами: это структурированные данные, и API умеет читать их обратно.
Подзадачи - другое: каждая становится отдельной карточкой на доске.

`assets/ticket-template.html` - готовый скелет структурированной задачи:
скопировать в `description` и заполнить разделы.
