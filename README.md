# Скилл YouGile

Скилл Claude Code для работы с [YouGile](https://yougile.com) через REST API v2.
Один файл на Python, только стандартная библиотека, зависимостей нет.
Нужен Python 3.10 или новее.

Покрыты все 69 операций спецификации: проекты, доски, колонки, задачи,
сотрудники, отделы, роли в проектах, чаты и групповые чаты, текстовые и
спринтовые стикеры, вебхуки, загрузка файлов, контакты CRM.

## Установка

```bash
git clone <этот-репозиторий> ~/.claude/skills/yougile-tracking
python3 ~/.claude/skills/yougile-tracking/scripts/yg.py setup
```

Setup спрашивает почту и пароль от аккаунта, создаёт ключ API и кладёт его в
связку ключей macOS. Нужен настоящий терминал: пароль читается скрытым вводом и
требует tty, через агента запустить не выйдет. Если ключ уже есть, положите его
в переменную `YOUGILE_API_KEY` или сохраните в связку ключей под именем
`yougile-api-key`. На Windows связки ключей нет, там работает только переменная
окружения.

Проверить установку: `python3 scripts/yg.py --selfcheck`. Проверка работает без
сети: она сверяет сборку запросов, а не доступ к сервису.

## Как пользоваться

```bash
YG="python3 ~/.claude/skills/yougile-tracking/scripts/yg.py"
$YG users_me '{}'
$YG projects_list '{}'
$YG tasks_create '{"title":"Починить форму входа","columnId":"<id-колонки>"}'
```

Аргументы передаются одним объектом JSON, `-` вместо него читает их из stdin.
`--list` печатает имена всех 70 инструментов, `"all": true` в списочном вызове
сам пролистает все страницы.

В `SKILL.md` лежит то, что читает агент: быстрые команды, правила разметки
описаний и подводные камни. В `references/api.md` полный справочник: все
инструменты, пагинация, поля задачи, цвета, вебхуки.

## Что где лежит

```
yougile-tracking/
├── SKILL.md                     инструкция для агента: команды, порядок работы, разметка
├── scripts/yg.py                клиент, он же CLI
├── references/api.md            справочник API: поля, цвета, пагинация, вебхуки

```

## Особенности API, учтённые в клиенте

Булевы значения в query обязаны быть строчными. На `True` с большой буквы
сервер отвечает `200`, а фильтр молча игнорирует: на живом аккаунте
`includeDeleted=True` вернул 18 задач там, где `true` возвращает 19, и ничто в
ответе на это не указывает. Query собирается через `urllib.parse.urlencode`,
булевы приводятся к нижнему регистру, так что ловушка не вернётся.

Списки отдаются страницами: по умолчанию 50 строк, максимум 1000, а
`paging.count` это размер страницы, а не общее число объектов. Принять его за
общее количество - самый простой способ незаметно работать с куском данных.

Удаления через DELETE у задач, досок, проектов и колонок нет. Удаление это
обновление с `"deleted": true`, а обратно такие объекты показываются только при
`includeDeleted: true`.

Цвет колонки задаётся числом от 1 до 16, цвет задачи строкой вида `task-red`.
Чеклисты перезаписываются целиком при каждой записи.
